# Validation: updates

Behaviour: [updates](../features/getting-started/updates.md). Rules: [projects, cache, FFmpeg and updates](../architecture/projects-and-setup.md#updates).

## Tests

`backend/tests/core/test_updates.py`, with a release ZIP and checksum built like the release workflow's and served from `file:` URLs:

- version comparison and the "What's new" lines of the release text;
- the ZIP of this platform found in the release assets, other platforms offered without download, pre-releases and non-version tags ignored;
- running from source is offered but not installable, with the reason;
- download: checksum verified, files unpacked with the executable bit, the ZIP removed; a wrong checksum unpacks nothing; cancel;
- apply: after the old process has ended, the executable and `_internal/` are replaced (files only in the old `_internal/` are gone), `models/`, `tools/`, `cache/` and `settings.json` are kept, the old files are in `updates/previous-*`, the new executable is started; a copy failing halfway restores the old files;
- API: the start check runs once per run, install and restart are refused without a downloadable update, skip and the setting are saved; offline, the start check answers normally and the Settings check reports an error;
- cleanup of `updates/`.

`frontend/src/updates.test.ts` covers when the window is offered at start.

## Browser check

With `VIDEOFLOW_UPDATE_URL` pointing to a release JSON for 0.40.0 (served from source): the update window opened first, without the FFmpeg or models windows, with the two "What's new" lines and the release address (running from source); Skip this version closed it and it did not open after a reload; Settings → Check for updates opened it again.

## Not yet checked

The download, replacement and restart of a packaged app on Windows and Linux are covered by the tests above but not yet run end to end: this needs two published releases that both contain the updater (from 0.37.0 to a later version).
