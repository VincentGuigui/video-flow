# Editor refinements and local AI settings — 2026-10-26

This revision supplements [interactive editor](interactive-editor.md) and [desktop shell](../architecture/desktop-shell.md). The native desktop architecture remains authoritative.

- Keep one Import media button. Remove panel numbers, local/workspace slogans, the project-folder header label and the assembly/focused status label. The logo closes the current project and opens the project home (see [projects](projects.md)).
- Keep automatic persistence and add Save immediately before Export. Untitled Save prompts for a name; the adjacent dropdown offers Save as. Where projects are stored, Save as, rename, launch and the recent list are described in [projects](projects.md).
- Resolution adaptation retains a reference canvas/transform so landscape → portrait → landscape restores the original size. Spatial edits invalidate the previous reference on the next adaptation.
- Remove curved flow connectors. Show green vertical boundary-alignment guides only during clip movement or trimming. Focus fits both timelines to the clip with up to two seconds of preceding/following context. Shift+wheel scrolls horizontally; Ctrl+wheel retains pointer-centered timeline zoom.
- Share a 12px legend/supporting-label constant. Fit media-library thumbnails within 160×90 with a 16:9 frame (entirely visible, see [workspace zones](workspace-zones.md)). Remove preview dimensions/fps and always show Drag the cursor to scrub.
- Show scale/crop tools in focused clip mode. Alternate Scale to fit / Scale to fill with corresponding icons. A background selector immediately follows scale/crop: color picker, transparent, or the current video blurred and scaled to fill. Store backgrounds per clip; apply them in preview and rendering.
- Export includes Save as MP4 video with quality, loudness normalization, progress and cancellation, followed by a native save dialog for the validated file. Status-bar minus/percentage/plus controls change Qt WebEngine page zoom independently of timeline zoom; the percentage resets to 100%.
- Model weights always reside inside the application `models/` subdirectory; `VIDEOFLOW_MODELS_DIR` always points there. Models are managed in their own **Manage AI models** window, opened from Settings → AI models → **Manage AI models…**, at startup when analysis is on by default and a required model is missing, and when an import waits for a missing model. It shows the models folder and every pinned model with its one-line goal (the `goal` field of `engines/manifest.toml`), purpose, licence, whether the current engine choices require it, its state (Missing / Obsolete / Up to date; the Obsolete badge explains that Update downloads the newer supported version), its exact **download size** (asked from the Hugging Face Hub metadata for the pinned files of the pinned revision when the window opens, metadata only, then cached per repository and revision in `models/download-sizes.json`; shown as unknown while the Hub was never reachable, and the total of missing models is only shown when every size is known) and its **size on disk** (the real files behind its cache folder, following the shared blob store, each counted once). Actions per model: Download / Update / Cancel (an up-to-date model shows a disabled "Already downloaded" button) and **Remove**, which deletes its files, including shared-store files no other model uses, after stopping the analysis workers that may have it loaded (refused while an import runs or the model downloads). A notice offers to download all missing required models with their total size. Models the editor does not use (`in_editor = false`: the DINOv2 shot embedder, kept for the analysis pipeline) are hidden. No implicit downloads. Compatible sidecars remain reusable without downloading.
- Offer deterministic or local Qwen summaries/keywords, Parakeet/Whisper ASR, speech device preference and import/export defaults. Choosing Qwen reveals its model and requests an explicit download when absent. Preferences persist in application-local settings.json.

Validation covers rotation and resolution round trips, exact render timing and layers, all three backgrounds, project copies and scoped deletion, model states and consent/cancellation. Native Qt smoke covers playback, focus/split/undo, zoom, home, blurred preview, MP4 and project copying. Platform qualification gates from [desktop shell](../architecture/desktop-shell.md) remain in force.

## Desktop inference dependencies

The `desktop` extra installs Qwen's PyTorch, Transformers and safetensors runtimes. Whisper remains an optional extra. Install one accelerator extra for ONNX speech, VAD and similarity inference as well. These are Python dependencies, separate from model weights in `models/`; installing them never downloads model weights. Existing source environments launch directly into the app so missing inference dependencies can be installed on request in component setup. Release CI explicitly installs Qwen, and the desktop build fails immediately if an inference runtime is missing instead of publishing an executable with missing hidden imports.

If Qwen's runtime is incomplete in a manually managed environment, analysis reports how to restore dependencies or use deterministic summaries. Existing models need no redownload. A source install can be repaired with `uv sync --extra desktop --extra cpu` in `backend/` (replace `cpu` with the chosen accelerator). The app must be restarted after repairing dependencies.

## Initial component setup

The initial **Install components** popup checks selected inference runtimes as well as model weights. Missing torch, Transformers, safetensors, ONNX tooling or the selected Whisper engine prompts even when all model weights exist. The same controls appear in **Settings → Manage AI models**. Source desktop builds offer explicit dependency installation into their Python environment using uv, with progress, cancellation, errors and a restart notice. Browser diagnostic mode cannot install packages. Frozen builds include Python runtimes; an incomplete build directs the user to reinstall the release rather than running a package manager inside an executable.

If CUDA is advertised, startup preloads the matching NVIDIA libraries and creates and runs a tiny ONNX session. Silent CPU fallback is shown as unavailable acceleration. The popup offers **Install CUDA libraries** (the installed ONNX GPU version's CUDA/cuDNN extras) or **Use CPU**, which persists the speech device preference. NVIDIA drivers and the Windows MSVC runtime remain system prerequisites. CUDA stays optional and CPU fallback remains available. Checks are cached for the process; restart after installation to validate the new environment. No model weights are downloaded by runtime installation.

Whisper's CPU ONNX dependency can overwrite a GPU/DML wheel. The in-app Whisper repair installs its engine/CTranslate2/AV packages without replacing the existing ONNX provider. Install the speech component first if its prerequisites are missing.
